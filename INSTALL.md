# Infinibay with LXD - Installation Guide

Complete guide for deploying Infinibay using LXD containers.

## Why LXD?

LXD provides native support for KVM/libvirt virtualization inside containers without requiring privileged mode.

| Feature | LXD | Docker |
|---------|-----|--------|
| **KVM Access** | ✅ Native via `unix-char` device | ⚠️ Requires `--privileged` |
| **Systemd Support** | ✅ Full systemd inside containers | ❌ Not recommended |
| **Nested Virtualization** | ✅ Designed for it | ⚠️ Limited |
| **Security** | ✅ Better isolation for VMs | ⚠️ Privileged mode risky |

## Prerequisites

### Supported Operating Systems

Infinibay's LXD deployment supports multiple Linux distributions with automatic package manager detection:

- **Debian/Ubuntu** - Uses `apt-get` (auto-detected)
- **RHEL/CentOS/Fedora/Rocky/AlmaLinux** - Uses `dnf` or `yum` (auto-detected)
- **openSUSE/SLES** - Uses `zypper` (auto-detected)
- **Arch/Manjaro/EndeavourOS** - Uses `pacman` (auto-detected)

**Note:** The setup script automatically detects your distribution and uses the appropriate package manager. No manual configuration needed.

**Note:** LXD installation path (snap vs native package) is also auto-detected.

### System Requirements

- **OS**: Linux (see supported distributions above)
- **CPU**: x86_64 with VT-x/AMD-V enabled (KVM support)
- **Memory**: Minimum 8GB RAM (16GB+ recommended)
- **Disk**: 50GB+ free space

### Check KVM Support

```bash
# Check if KVM is available
ls -l /dev/kvm

# Install cpu-checker
sudo apt install cpu-checker

# Verify KVM acceleration
sudo kvm-ok

# Expected output:
# INFO: /dev/kvm exists
# KVM acceleration can be used
```

## Installation

### Step 1: Clone Repository

```bash
cd ~
git clone https://github.com/infinibay/infinibay.git
cd infinibay/lxd
```

### Step 2: Run Setup Script

```bash
sudo ./setup.sh
```

The setup script will:
- Detect your Linux distribution and package manager
- Install system dependencies using your distro's package manager
- Auto-detect LXD installation path (snap or native)
- Install LXD (via snap or native package)
- Install lxd-compose
- Initialize LXD with default configuration
- Add your user to `lxd` group
- Create `~/.config/lxc/config.yml` for lxd-compose
- Create data directories
- Generate `.env` file with secure passwords

### Step 3: Activate lxd Group

**CRITICAL STEP:** The setup script adds you to the `lxd` group, but you need to activate it.

**Option 1 - Quick (current session only):**
```bash
newgrp lxd
```
This opens a new shell with the `lxd` group active. Stay in this shell for the remaining steps.

**Option 2 - Permanent (requires logout):**
```bash
logout
# Then login again
```

**Verify you're in the group:**
```bash
groups | grep lxd
# Should show 'lxd' in the output
```

### Step 4: Configure Environment Variables

The `setup.sh` script automatically creates a `.env` file with secure auto-generated passwords. You should review and customize it:

**Option A: Edit the auto-generated `.env` (RECOMMENDED)**

```bash
nano .env
```

The file has already been created by `setup.sh` with secure passwords. You should customize:

```bash
# Admin credentials (CHANGE THESE!)
ADMIN_EMAIL=admin@yourdomain.com
ADMIN_PASSWORD=auto_generated_16_char_password  # CHANGE THIS!

# Database password (auto-generated by setup.sh - already secure)
DB_PASSWORD=auto_generated_25_char_password  # Can keep or change

# Host IP (auto-detected, verify it's correct)
HOST_IP=192.168.1.100

# Libvirt network (default is usually fine)
LIBVIRT_NETWORK_NAME=default
```

**Option B: If you prefer to configure before running setup.sh**

```bash
cp .env.example .env
nano .env
# Customize all values
# Then run: sudo ./setup.sh
# setup.sh will detect and preserve your existing .env
```

**Security Note:** While `setup.sh` auto-generates secure passwords for both `DB_PASSWORD` and `ADMIN_PASSWORD`, you should **change `ADMIN_PASSWORD`** to something memorable that only you know. Auto-generated passwords are secure but not personalized.

```bash
# Check that lxd-compose recognizes the project
lxd-compose project list

# Expected output:
# | PROJECT NAME | DESCRIPTION                       | # GROUPS |
# |--------------|-----------------------------------|----------|
# | infinibay    | Infinibay VDI Management Platform | 4        |
```

### Step 6: Deploy and Start Infinibay

**Simple - just one command:**

```bash
./run.sh
```

**What happens (takes 5-10 minutes on first run):**

This intelligent default workflow handles everything automatically:

1. **Checks if environment exists** → Creates if not:
   - Generates LXD profiles with correct paths
   - Downloads Ubuntu container images (first time only)
   - Creates 4 containers:
     - `infinibay-postgres` (PostgreSQL database)
     - `infinibay-redis` (Redis cache)
     - `infinibay-backend` (Node.js API with KVM access)
     - `infinibay-frontend` (Next.js UI)
   - Configures resource limits (CPU, RAM)
   - Mounts shared directories:
     - `/opt/infinibay` → Your code (shared)
     - `/data` → Persistent data (per container)

2. **Checks if containers are running** → Starts if stopped

3. **Checks if provisioned** → Provisions if not (tracked via LXD metadata):
   - **PostgreSQL container:**
     - Installs PostgreSQL 14
     - Configures data directory `/data/pgdata`
     - Creates `infinibay` database and user
     - Enables network access for other containers

   - **Redis container:**
     - Installs Redis server
     - Configures persistence to `/data/redis`
     - Enables network access

   - **Backend container:**
     - Installs Node.js 20.x LTS + npm
     - Installs Rust toolchain (for native modules)
     - Installs libvirt + KVM dependencies
     - Configures `/dev/kvm` device access
     - Sets up libvirt storage pool at `/data/libvirt`
     - Creates systemd service

   - **Frontend container:**
     - Installs Node.js 20.x LTS + npm
     - Creates systemd service
     - Sets up log directories

4. **Shows access URLs when ready**

**Note:** This intelligent default behavior means you can run `./run.sh` anytime to ensure everything is up and running. It automatically skips already-completed steps.

## Common Operations

### Smart Default Workflow (Recommended)

```bash
# One command does everything
./run.sh              # Creates, provisions, and starts everything

# Fresh start (destroy and recreate)
./run.sh redo         # or: ./run.sh rd

# Quick status check
./run.sh status       # or: ./run.sh s
```

### Managing Containers

```bash
# Smart default (recommended)
./run.sh              # Does everything automatically

# Manual step-by-step commands (if you prefer explicit control)
./run.sh apply        # Shortcuts: a, ap - Create containers
./run.sh provision    # Shortcuts: p, pr - Install software

# Container management
./run.sh status       # Shortcuts: s, st - Check status
./run.sh destroy      # Shortcuts: d, de - Remove containers
./run.sh redo         # Shortcut: rd - Destroy and recreate (fresh start)
./run.sh restart      # Shortcuts: r, re - Legacy alias for redo

# Execute commands
./run.sh exec backend bash    # Shortcuts: e, ex
./run.sh logs backend         # Shortcuts: l, lo

# Update profiles only
./run.sh setup-profiles       # Shortcut: sp

# View project info
lxd-compose project list

# View container status
lxc list
```

**Complete shortcut reference:**
| Command | Shortcuts | Description |
|---------|-----------|-------------|
| `apply` | `a`, `ap` | Create and start containers |
| `provision` | `p`, `pr` | Install software in containers |
| `redo` | `rd` | Destroy and recreate everything |
| `destroy` | `d`, `de` | Stop and remove all containers |
| `restart` | `r`, `re` | Legacy alias for redo |
| `status` | `s`, `st` | Show container status |
| `setup-profiles` | `sp` | Update LXD profiles only |
| `exec` | `e`, `ex` | Execute command in container |
| `logs` | `l`, `lo` | Follow container logs |

### Accessing Containers

```bash
# Open shell in container
lxc exec infinibay-backend -- bash

# View logs (if service is configured)
lxc exec infinibay-backend -- journalctl -f

# Execute command
lxc exec infinibay-postgres -- ls -la /var/lib/postgresql
```

### Snapshots and Backups

```bash
# Create snapshot before updates
lxc snapshot infinibay-backend backup-$(date +%Y%m%d)

# List snapshots
lxc info infinibay-backend

# Restore from snapshot
lxc restore infinibay-backend backup-20251120

# Export container as backup
lxc export infinibay-backend infinibay-backend-backup.tar.gz

# Import backup
lxc import infinibay-backend-backup.tar.gz
```

## Troubleshooting

### "No project selected" Error

```bash
# Wrong:
lxd-compose apply

# Correct:
lxd-compose apply infinibay
```

### "Unable to read the configuration file" Error

This means lxd-compose can't find `~/.config/lxc/config.yml`.

**Solution:**
```bash
# The setup script should have created this file
# If it's missing, you can create it manually:
mkdir -p ~/.config/lxc
cat > ~/.config/lxc/config.yml << 'EOF'
default-remote: local
remotes:
  local:
    addr: unix://
    protocol: lxd
    public: false
  images:
    addr: https://images.lxd.canonical.com
    protocol: simplestreams
    public: true
EOF
```

### "Permission denied" on LXD Socket

This means you're not in the `lxd` group or haven't activated it.

**Check:**
```bash
groups | grep lxd
```

**If `lxd` doesn't appear:**
```bash
# Add yourself to the group
sudo usermod -aG lxd $USER

# Then activate it
newgrp lxd
```

**If `lxd` appears but still getting errors:**
```bash
# You need to activate the group change
newgrp lxd
```

### Container Won't Start

```bash
# Check container status
lxc list

# View container logs
lxc info infinibay-backend --show-log

# Start manually and watch logs
lxc start infinibay-backend
lxc exec infinibay-backend -- journalctl -f
```

### Environment Setup Fails

**Symptom:** `./run.sh` fails during provisioning

**Solutions:**
```bash
# Check that .env file exists and is properly configured
ls -la .env
cat .env

# Use redo to start fresh (destroys and recreates everything)
./run.sh redo

# Check individual container logs
./run.sh logs backend
./run.sh logs postgres
./run.sh logs redis
./run.sh logs frontend
```

### Want to Force Re-provisioning

**Solution 1:** Use `./run.sh redo` (destroys and recreates everything)
```bash
./run.sh redo
```

**Solution 2:** Manually clear provisioning state for specific containers
```bash
lxc config unset infinibay-backend user.provisioned
lxc config unset infinibay-frontend user.provisioned
lxc config unset infinibay-postgres user.provisioned
lxc config unset infinibay-redis user.provisioned

# Then run smart default
./run.sh
```

### Package Installation Fails on My Distro

**Symptom:** Setup script fails to install packages

**Solutions:**
```bash
# Check that your distribution is supported
# See Prerequisites section for list of supported distros

# Verify package manager is available
command -v apt-get    # For Debian/Ubuntu
command -v dnf        # For RHEL/CentOS/Fedora
command -v zypper     # For openSUSE
command -v pacman     # For Arch

# Check setup.sh output for package manager detection messages
sudo ./setup.sh

# If your distro should be supported but isn't detected:
# Please file an issue at https://github.com/infinibay/infinibay/issues
```

### Reset Everything

```bash
# Option 1: Use redo command (simplest)
./run.sh redo

# Option 2: Manual reset
# Stop and delete all containers
lxd-compose destroy infinibay

# Or manually:
lxc delete infinibay-backend infinibay-frontend infinibay-postgres infinibay-redis --force

# Delete data (WARNING: DELETES ALL DATA)
sudo rm -rf /var/lib/infinibay/

# Start fresh
sudo ./setup.sh
newgrp lxd
./run.sh
```

## Next Steps After Provisioning

**Note:** The smart default `./run.sh` handles provisioning automatically. These steps are for manual configuration if needed.

After provisioning is complete, you can:

### 1. Install npm Dependencies

```bash
# Backend
./run.sh exec backend bash
cd /opt/infinibay/backend
npm install

# Frontend (in another terminal or after exiting)
./run.sh exec frontend bash
cd /opt/infinibay/frontend
npm install
```

### 2. Build Native Modules

```bash
# Backend: Build libvirt-node (Rust → Node.js bindings)
./run.sh exec backend bash
cd /opt/infinibay/libvirt-node
npm install
npm run build
```

### 3. Run Database Migrations

```bash
./run.sh exec backend bash
cd /opt/infinibay/backend
npm run db:migrate
```

### 4. Start Services

```bash
# Backend
./run.sh exec backend systemctl start infinibay-backend

# Frontend
./run.sh exec frontend systemctl start infinibay-frontend

# Check status
./run.sh exec backend systemctl status infinibay-backend
./run.sh exec frontend systemctl status infinibay-frontend
```

### 5. Access Infinibay

```bash
# Find frontend IP
lxc list infinibay-frontend

# Open in browser
# http://<frontend-ip>:3000
```

## FAQ

### Q: Can I use this for production?

**A:** Yes! The LXD implementation is production-ready with automated provisioning and intelligent orchestration. It provides the same functionality as the native installer with better isolation, snapshots, and easier backup/restore capabilities.

### Q: Do I need to run apply, then provision, then start?

**A:** No! Just run `./run.sh` with no arguments. It intelligently handles all steps:
- Creates containers if they don't exist
- Starts containers if they're stopped
- Provisions if not already done (tracked via LXD metadata)
- Skips already-completed steps automatically

This is the recommended workflow for both initial setup and ongoing management.

### Q: What if I want to start fresh?

**A:** Run `./run.sh redo` (or the shortcut `./run.sh rd`). This destroys everything and recreates from scratch. Useful when:
- Testing changes to provisioning scripts
- Recovering from configuration errors
- Wanting a clean slate

### Q: Which Linux distributions are supported?

**A:** Infinibay LXD deployment supports 4 major distribution families with automatic package manager detection:
- **Debian/Ubuntu** - Uses `apt-get`
- **RHEL/CentOS/Fedora/Rocky/AlmaLinux** - Uses `dnf` or `yum`
- **openSUSE/SLES** - Uses `zypper`
- **Arch/Manjaro/EndeavourOS** - Uses `pacman`

The setup script automatically detects your distribution and uses the appropriate package manager. No manual configuration needed.

### Q: What's the difference between LXD and the native installer?

**A:**
- **LXD**: Containers with better isolation, easier backup/restore, snapshots, smart orchestration
- **Native**: Installs directly on host, simpler architecture
- Both are production-ready, choose based on your preference

### Q: Can I run multiple Infinibay instances?

**A:** Yes! Edit `envs/infinibay.yml` and create a second project with different container names and ports.

### Q: How do I update to the latest version?

**A:**
```bash
cd ~/infinibay/lxd
git pull
./run.sh
```
